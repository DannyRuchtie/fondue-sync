# Public image component coverage

The additive `recipes/media-components.mjs` module references the six approved files in `fixtures/media/manifest.json`. Images remain native image fills on editable layers; the component or page is never a screenshot. Existing Card icon parts and the PDF AssetInput retain their IDs and contents.

| Native recipe                         | Released public parts                                             | Reviewed finite configurations                                                                                                                                                                                                         |
| ------------------------------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `components/Card.BannerImage`         | `Card.Banner` + `Card.BannerImage`                                | Parent `size=small/large` × image `fit=cover/contain` × `padding=none/small/medium/large`: 16 variants. Source ratios 3:1 and 9:6 at the Card minimum width of 240px. Padding is 0, 12, 24 and 32px, bound to the exact source tokens. |
| `components/Card.ThumbnailImage`      | `Card.ThumbnailImage`                                             | One native default, 40 × 40px, contain, medium radius. The containing Card supplies its grid placement and 12px margins.                                                                                                               |
| `components/AssetInput/image-preview` | `AssetInput.Root`, `Preview`, `PreviewImage`, `Title`, `Metadata` | `orientation=horizontal/vertical` × `isOpen=false/true`: four variants. A single image uses contain, with the source 56px horizontal preview or 128px vertical preview height.                                                         |

All recipes remain partial. `src` and `alt` are open content, not invented enumerations. Banner size belongs to the containing Banner, not the image prop interface. AssetInput widths of 360px horizontally and 280px vertically are sample containers; its 48px vertical title/caret row derives from the 16px caret and two 16px paddings. Native image fills use `FILL` for cover and `FIT` for contain. The real fixture content is illustrative; source loading behavior, alternative-text semantics, arbitrary resizing, browser text ellipsis, events, image grids and overlay compositions require separate application and native review.

Source evidence: released `Card/Card.ts`, `Card/CardBanner.tsx`, `Card/CardContent.tsx`, `Card/styles/card.module.scss`, `AssetInput/AssetInput.tsx`, `AssetInput/AssetInputRoot.tsx`, `AssetInput/AssetInputPreview.tsx`, `AssetInput/AssetInputPreviewImage.tsx`, and `AssetInput/styles/asset-input.module.scss` in the pinned release snapshot. The focused test checks these declarations, exact metrics, fit mappings, fixture bytes and non-collision with existing functional recipe IDs. No new native runtime acceptance is claimed by these source tests.
